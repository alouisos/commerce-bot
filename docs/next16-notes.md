# Next.js 16 notes for this repo

Installed: `next@16.4.5`, React 19.3. Source of truth: `node_modules/next/dist/docs/` (paths below are relative to it). Where this contradicts the plan, the docs win.

## proxy.ts replaces middleware.ts
- `middleware` is deprecated and renamed `proxy`; the exported function is `proxy` (or default export). File lives at `src/proxy.ts` (same level as `app/`). One proxy per project. (`01-app/03-api-reference/03-file-conventions/proxy.md`, `01-app/02-guides/upgrading/version-16.md` section "middleware to proxy")
- Runs on the **Node.js runtime**, not edge; the `runtime` config is not allowed in it (throws). So DB or Better Auth session lookups are possible, but the docs say to treat proxy as an optimistic gate and not rely on shared modules or globals. Pass data on with headers, cookies, rewrites, redirects.
- Without a `matcher` it runs on every request including `_next/static`, `_next/image`, `public/`. Always set one. Matcher values must be static constants. Example excluding api and assets: `'/((?!api|_next/static|_next/image|.*\\.png$).*)'`.
- When a proxy exists, Next buffers the request body (default cap 10MB, experimental `proxyClientMaxBodySize`) (`01-app/03-api-reference/05-config/01-next-config-js/proxyClientMaxBodySize.md`). Keep proxy off the public `/api/widget/*` and upload paths unless needed.
- Config flags renamed too, e.g. `skipMiddlewareUrlNormalize` is now `skipProxyUrlNormalize`.

## Route handlers and streaming
- `app/**/route.ts` exports `GET/POST/PUT/PATCH/DELETE/HEAD/OPTIONS`. If `OPTIONS` is not exported, Next auto-implements it (so export it explicitly for widget CORS). A `route.ts` cannot coexist with a `page.tsx` at the same path. (`.../03-file-conventions/route.md`, `01-app/01-getting-started/15-route-handlers.md`)
- Handlers use Web `Request`/`Response`; `NextRequest` adds `cookies` and `nextUrl`. Return a `Response` wrapping a `ReadableStream` for streaming (SSE/chat). The streaming example in the docs uses the Vercel AI SDK; we use the raw Anthropic SDK stream into `new Response(stream, { headers })` instead.
- Buffering: nginx-style reverse proxies buffer by default; send `X-Accel-Buffering: no`. Gzip/brotli can delay chunks; CDNs may buffer. Safari buffers the first 1024 bytes. `curl` needs `-N` and newline-terminated chunks to look streamed. (`01-app/02-guides/streaming.md`, "Disabling buffering"/"Compression")
- `GET` handlers are not cached by default.
- **`params` is a Promise**: `{ params }: { params: Promise<{ id: string }> }` then `await params`. Globally available typed helper `RouteContext<'/users/[id]'>` (types generated by `next dev`, `next build` or `next typegen`).
- `cookies()`, `headers()`, `draftMode()` must be awaited; synchronous access is fully removed in 16. `searchParams` in `page` is also a Promise. `PageProps<'/x/[id]'>` and `LayoutProps` helpers exist. (`.../upgrading/version-16.md` "Async Request APIs")

## Cache Components is OFF
`create-next-app` enabled `cacheComponents` and `partialPrefetching`; we removed both from `next.config.ts` because the admin and widget API are fully dynamic per request. Do not re-enable without reading `01-app/03-api-reference/05-config/01-next-config-js/cacheComponents.md`: it forbids `dynamic`/`revalidate`/`runtime` exports and requires Suspense around runtime data. With it off, route handlers and pages that read cookies/headers/DB are dynamic by default.

## Server actions and forms
- Actions are POST requests with a **1MB body cap by default**; configure `experimental.serverActions.bodySizeLimit` (e.g. `'10mb'`, number of bytes or bytes-style string). The limit counts the raw multipart body, so leave 10-20KB headroom over the file size. For knowledge-base file uploads prefer a route handler (`request.formData()`) with our own size check, otherwise raise `bodySizeLimit`. (`.../05-config/01-next-config-js/serverActions.md`)
- CSRF: `Origin` is compared to `Host`/`X-Forwarded-Host`; behind a proxy that rewrites the host, add `experimental.serverActions.allowedOrigins`. Applies in production too.
- Actions are public endpoints: always authenticate and authorize inside each action, not only at render. Self-hosted multi-instance: set `NEXT_SERVER_ACTIONS_ENCRYPTION_KEY` to a stable shared key. (`01-app/02-guides/server-actions.md`)
- A `<form action={fn}>` passes `FormData` to `fn`; `Object.fromEntries(formData)` includes extra `$ACTION_*` keys. (`01-app/02-guides/forms.md`)
- After mutating, call `revalidatePath`, `updateTag` or `refresh` to re-render in the same round trip; `revalidateTag(tag, profile)` is stale-while-revalidate and does not re-render the action response.

## Other breaking changes that matter here
- Turbopack is the default for `next dev` and `next build`; a custom `webpack` config makes `next build` fail. Use `--webpack` to opt out. (`.../version-16.md`)
- `next lint` is removed; `npm run lint` is plain `eslint` with flat config (`eslint.config.mjs`).
- `typecheck` script runs `next typegen` first because `LayoutProps`/`PageProps`/`RouteContext` are generated global types (plain `tsc` fails on a fresh checkout).
- Node.js 20.9+ required; AMP and runtime config (`publicRuntimeConfig`) removed.
